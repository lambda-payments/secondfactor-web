What Are OTP Delivery Logs?

An OTP delivery log is the record of one verification request: where the code was sent, which channel carried it, whether it was delivered and what the send cost.

SecondFactor routes each code for you, so the log is where you see what the routing engine did. Every request shows its delivery status, the delivering channel and its price.

The same record is available three ways: as OTP logs in your dashboard, as a verification you can fetch through the API, and as webhook events sent to your server.

Read Status and Cost From the API

Fetch a verification with the SID returned when you sent the code. The response is the same verification object every endpoint returns.

delivery_status is the state of the message, status is the state of the code, and price is what the send cost. Use price for exact amounts: the charged value in webhooks is rounded to two decimal places.

What Each Delivery Status Means

Four delivery statuses cover the life of a message.

Pending

SecondFactor is still trying channels. No channel has confirmed delivery yet.

Sent

The last channel accepted the message and no delivery receipt has arrived. This can be the final status.

Delivered

A carrier confirmed that the message reached the recipient.

Failed

Every eligible channel was tried and each one failed.

Understand What You Are Charged For

Billing follows a few fixed rules, so the cost in your logs can be reconciled against your balance.

One Charge per Accepted Send

Each accepted send is one charge. The charge stands whether or not the message is delivered.

Refused Sends Are Free

A send that is refused with an error is not charged.

Checking and Fetching Are Free

Verifying a code and reading a verification’s status cost nothing.

Sending Again Is a New Charge

A new code to the same number is a new send. Limit how often users can request one.

Frequently Asked Questions

Write to support@secondfactor.ai for anything not covered here.

Where Can I See Whether an OTP Was Delivered?+

In the OTP logs in your dashboard, in the delivery_status field when you fetch a verification, or through the otp.delivered and otp.failed webhooks.

Is the Cost Shown for Each Request?+

Yes. Each verification has a price field with the cost of that send as a decimal string, and price_unit is always USD.

Am I Charged for an OTP That Isn’t Delivered?+

Yes. An accepted send is charged whether or not the message is delivered. A send that is refused with an error is not charged.

Does It Cost Anything to Check Delivery Status?+

No. Fetching a verification is free and doesn’t count as a check attempt on the code.

Why Does a Delivery Stay on Sent?+

Sent means the last channel accepted the message but no delivery receipt has come back. Some routes never return one, so Sent can be final.

Will I Receive a Webhook for Every OTP?+

Webhooks are best-effort. If the last channel accepts a message but never returns a receipt, neither otp.delivered nor otp.failed is sent. Confirm events that matter by fetching the verification.

How Often Can I Poll for Delivery?+

At most once a second. Stop when the delivery status is Delivered or Failed, or when the code’s expiry time has passed.
