Track Delivery and Verification Separately

These webhook events tell you when a code arrives, fails, is verified or expires.

Delivered

otp.delivered: a carrier confirmed delivery. The user still needs to enter the code.

Failed

otp.failed: every eligible channel was tried and none confirmed delivery.

Verified

otp.verified: the user’s code was accepted.

Expired

otp.expired: the code expired before it was successfully verified.

Understand What You Are Charged For

Sending a code creates a charge. Checking the code and fetching a pending verification are free.

One Charge per Accepted Send

Each accepted send is one charge. The charge stands whether or not the message is delivered.

Refused Sends Are Free

A send that is refused with an error is not charged.

Checking and Fetching Are Free

Verifying a code and reading a verification’s status cost nothing.

Sending Again Is a New Charge

A new code to the same number is a new send. Limit how often users can request one.

Frequently Asked Questions

Write to support@secondfactor.ai for anything not covered here.

Where Can I See Whether an OTP Was Delivered?+

Check the OTP logs in your dashboard or configure webhooks to receive otp.delivered and otp.failed events in your application.

Is the Cost Shown for Each Request?+

Yes. Your dashboard shows the cost of each OTP request. Webhooks also include a charged amount, rounded to two decimal places.

Am I Charged for an OTP That Isn’t Delivered?+

Yes. An accepted send is charged whether or not the message is delivered. A send that is refused with an error is not charged.

Does It Cost Anything to Check Delivery Status?+

No. Fetching a verification is free and doesn’t count as a check attempt on the code.

Does Delivered Mean the User Has Verified Their Number?+

No. Delivered means a carrier confirmed delivery. The user must still enter the code, and your application must check it successfully before treating the number as verified.

Can I Fetch a Verification After It Is Complete?+

No. The fetch endpoint returns pending verifications only. A 404 cannot distinguish an approved verification from an expired, locked or unknown one. Keep the outcome from the check response and webhooks in your application.

How Often Can I Poll for Delivery?+

Poll no more than once per second, and stop at the first 404 or your own timeout. Polling tells you when a verification is no longer pending; use the check response and webhooks to learn the outcome.
