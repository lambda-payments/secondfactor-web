How Routing and Fallback Work

SecondFactor checks the available channels, attempts delivery and handles fallback for each request.

Request an OTP

Post the number in E.164 format to the Verifications endpoint. SecondFactor generates the code and returns a verification SID.

Check Eligible Channels

The engine keeps the channels that are enabled on your account, can reach this number and are allowed by your delivery rules.

Attempt Delivery

The lowest-cost eligible channel is tried first unless a channel preference applies to your pricing plan. Delivery confirmation stops fallback.

Fall Back if Needed

After eight seconds without delivery confirmation, SecondFactor tries the next eligible channel. Attempts stop when delivery is confirmed or all eligible channels have been tried.

Send a Code and Track Delivery

Post the phone number to /Verifications and store the returned verification SID. A 201 response confirms that the request was accepted; delivery happens afterward.

Use webhooks to receive delivery updates. An otp.delivered event identifies the channel that confirmed delivery and the request’s cost so far.

Frequently Asked Questions

Write to support@secondfactor.ai for anything not covered here.

Can I Choose Which Channel an OTP Uses?+

On per-channel pricing, the optional Channel parameter sets which channel to try first. Other eligible channels remain available for fallback. On blended pricing, SecondFactor ignores this preference and uses the lowest-cost eligible route.

How Long Does SecondFactor Wait Before Switching Channels?+

Eight seconds. If the first channel has not confirmed delivery by then, the next eligible channel is tried.

Do I Need Every Channel Connected for Fallback to Work?+

No. Fallback needs at least two enabled channels that can reach the recipient. With one channel connected, requests are sent on that channel only.

Am I Charged Again When an OTP Falls Back to Another Channel?+

Each accepted send is a single charge. Sending a new code to the same number is a new send and is charged again, so limit how often users can press “send again”.

What Happens When Every Channel Fails?+

SecondFactor sends an otp.failed event to your configured webhook. Review the request in your dashboard before deciding whether to send another code.

How Do I See Which Channel Delivered a Code?+

Check the otp.delivered webhook or the OTP logs in your dashboard. The initial API response arrives before delivery and does not identify the confirmed delivery channel.

Can I Test Routing and Fallback Before Integrating?+

Yes. Use your free credits in the PIE Playground to send a real OTP to your own number, inspect the route it took and verify the code you receive.
