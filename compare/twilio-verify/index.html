Pricing, channels and verification

Reviewed November 4, 2026

SecondFactor generates, sends and verifies OTPs through four messaging channels: SMS, WhatsApp, Viber and RCS. Twilio Verify also supports voice, email, TOTP, push and passkeys.

Twilio Verify charges $0.05 per successful verification, plus delivery costs. SecondFactor charges once per accepted OTP request, including code generation, delivery, fallback and verification. The rate depends on the destination country.

Delivery & monitoring

Automatic routing and fallback

SecondFactor routes each OTP by destination cost

SecondFactor checks destination pricing and the channels available to your account and the recipient. It sends through the lowest-cost eligible channel, then tries the next channel if delivery is not confirmed.

Fallback is included in the OTP request price. Resending a code creates a new request and a separate charge. To use fallback, you need at least two channels available for the recipient.

Twilio routes between supported channels

Twilio Verify uses the channel specified in your request. Its automatic routing options include upgrading SMS to RCS and falling back to SMS from supported channels. WhatsApp-first routing is available through configuration with Twilio.

Track delivery status and cost per request

SecondFactor’s OTP logs show the destination, delivery channel, status and cost of each request. Use them to investigate failed deliveries and monitor spending. Signed webhooks send delivery and verification updates to your server.

Integration

Moving from Twilio Verify

API documentation ↗

SecondFactor uses the same send and code-check endpoint paths as Twilio Verify v2. Update the API host, credentials and Service SID, then adapt your application to SecondFactor’s verification responses. The examples below show the changes to a send request.

1. Update the send call

Replace your Twilio credentials with a SecondFactor API key and Service SID. Omit Channel to use automatic routing. Send API requests from your server.

2. Handle code-check responses

A correct code returns 200 VERIFIED. A wrong code with attempts left returns 422. Expired, locked or already-used codes return 409.

3. Test retries and delivery

Use a new Idempotency-Key per send action and reuse it only when retrying that action. Test sends, checks and resends on a number you own before moving traffic.

Questions

Frequently asked questions

Do I need to connect every channel?

No. Start with the channels you need. WhatsApp requires a WhatsApp Business Account and approved authentication templates; other channels have their own sender requirements. Fallback needs at least two channels that can reach the recipient. Channel requirements →

Can I keep generating my own codes?

Yes. SecondFactor’s send endpoint accepts an optional Code. If you supply it, your application must check it. Omit it to let SecondFactor generate and verify the code.

What happens if every delivery attempt fails?

SecondFactor sends an otp.failed webhook. Review the request’s delivery status before sending another code. A new send is a separate request and charge.

Is there a sandbox?

No. Accepted sends use real delivery channels. New accounts receive free credits for testing in the PIE Playground. Use a number you own, inspect the route and verify the code. Mock the API in automated tests.

Are the calculator results a quote?

No. They use published destination rates or the rates you enter. The estimate assumes one send and one completed verification per user. Retries, failed attempts, sender fees, negotiated rates and your mix of destinations can change the total. Contact us about your traffic →
